# State Flow Checklist

사용자 행동, 시스템 반응, 상태 전이, 오류 복구를 설계할 때 사용한다. 버튼을 누른 뒤의 흐름, async 처리, 위험 행동, onboarding, 권한 요청을 정리할 때 읽는다.

## 1. 플로우 기본 표

| Step | 사용자 행동 | 시스템 반응 | 화면 상태 | 데이터 상태 | 피드백 | 다음 행동 |
|---|---|---|---|---|---|---|
| 1 |  |  | idle/loading/success/error/empty |  |  |  |

작성 기준:

- 사용자 행동과 시스템 반응을 같은 문장에 섞지 않는다.
- 화면 상태와 데이터 상태를 분리한다.
- 피드백은 시각 변화, 문구, 알림, 포커스 이동, disabled 상태 중 무엇인지 적는다.

## 2. 상태 전이

| 현재 상태 | 이벤트 | 조건 | 다음 상태 | 부수 효과 | 실패 시 |
|---|---|---|---|---|---|
| idle | submit | valid input | loading | request start | error |

자주 빠지는 상태:

- 초기 로딩
- 빈 데이터
- 부분 성공
- 중복 클릭 방지
- 요청 취소
- 세션 만료
- 권한 변경
- 오프라인 또는 네트워크 지연
- 삭제 후 복구 가능 기간

## 3. 입력과 검증

| 입력 | 형식 | 필수 여부 | 즉시 검증 | 제출 시 검증 | 오류 문구 방향 | 접근성 |
|---|---|---|---|---|---|---|
|  |  |  | yes/no | yes/no |  | aria-describedby/focus |

## 4. 위험 행동

| 행동 | 위험 | 예방 장치 | 확인 문구 | 되돌리기 | 로그/감사 | 권한 |
|---|---|---|---|---|---|---|
| 삭제 | 데이터 손실 | preview/confirm |  | undo/restore/no |  |  |

위험 행동 기준:

- 되돌릴 수 없으면 확인 전에 영향 범위를 보여준다.
- 되돌릴 수 있으면 확인 모달보다 undo를 우선 검토한다.
- 결제, 개인정보, 외부 발송, 대량 변경은 로그와 권한을 같이 본다.

## 5. 다이어그램 선택

| 상황 | 추천 |
|---|---|

| QA 연결이 핵심 | 상태 전이표 |

## 6. 검증 질문

- 모든 주요 행동에 즉시 이해 가능한 피드백이 있는가?
- 실패했을 때 사용자가 같은 실수를 반복하지 않게 안내하는가?
- 로딩 중 중복 입력, 뒤로 가기, 화면 이탈을 어떻게 처리하는가?
- 성공 후 다음 행동과 완료감을 모두 제공하는가?
- 키보드, 스크린리더, 터치 환경에서 같은 흐름을 완료할 수 있는가?
