# 루트와 시간 예산
이 문서는 공항, 역, 숙소, 관광지, 식당, 쇼핑지를 실제 이동 가능한 순서로 배치할 때 읽는다.

## 1. 시간 예산 구성
각 일정 블록은 아래 시간을 분리해 계산한다.

- 순수 이동시간
- 대기시간
- 환승시간
- 도보 접근시간
- 티켓 구매 또는 입장 대기
- 수하물 찾기 또는 짐 보관
- 체크인/체크아웃
- 식사 대기와 식사 시간
- 관광지 관람 시간
- 쇼핑 시간
- 휴식 버퍼

단순 지도 이동시간만 합산하지 않는다. 실제 일정표에는 최소한 `이동/대기/활동/버퍼`를 함께 표시한다.

## 2. 교통수단별 고려사항
| 이동수단 | 고려할 항목 |
|---|---|
| 자가용/렌터카 | 주차장, 주차비, 톨비, 운전 피로, 음주 불가, 러시아워, 짐 보관 |
| 기차/고속철 | 역 접근, 발권, 플랫폼 이동, 수하물, 환승, 막차 |
| 버스 | 배차 간격, 정류장 위치, 교통 체증, 캐리어 탑승 불편 |
| 지하철/대중교통 | 환승 횟수, 계단/엘리베이터, 출퇴근 혼잡, 교통카드 |
| 택시/라이드쉐어 | 피크요금, 호출 가능성, 짐 적재, 언어/결제 |
| 항공 | 공항 접근, 탑승 수속, 보안검색, 출입국 심사, 수하물, 지연 |
| 배/페리 | 항구 접근, 탑승 마감, 결항 리스크, 멀미, 수하물 |

## 3. 탑승 수속 버퍼
- 국내선, 국제선, 페리, 장거리 열차의 권장 도착 시간은 항공사/운영사/공항/항구 기준을 최신 확인한다.
- 기본 안전 가정은 국내선 90~120분 전, 국제선 150~180분 전, 성수기/연휴/위탁수하물/아이 동반은 더 길게 둔다.
- 공항까지 이동시간에는 집에서 터미널까지의 교통 체증, 주차, 셔틀, 체크인 카운터 이동을 포함한다.
- 도착 후에는 입국 심사, 수하물 수취, 유심/eSIM 문제, 교통권 구매, 환전, 숙소 이동 시간을 둔다.

## 4. 루트 설계 순서
1. 확정된 항공/열차/숙소/식당 예약을 고정점으로 둔다.
2. 고정점 사이의 시작 위치와 종료 위치를 연결한다.
3. 같은 권역의 관광지, 식당, 카페, 쇼핑지를 묶는다.
4. 방문 시간 제약이 있는 장소를 먼저 배치한다.
5. 식사 시간과 휴식 시간을 확보한다.
6. 이동 방식별 실제 소요와 버퍼를 넣는다.
7. 너무 빡빡하면 우선순위 낮은 후보를 예비 목록으로 뺀다.

## 5. 첫날 루트
- 공항/역 도착 시간이 이르면 숙소 체크인 전 짐 보관 가능성을 먼저 본다.
- 캐리어가 있으면 공항/역에서 숙소 방향으로 이동하는 중간 실내 명소나 식당만 고려한다.
- 장거리 이동 직후에는 야외 장시간 도보보다 짧은 산책, 식사, 숙소 주변 적응을 우선한다.
- 늦은 도착이면 식당 영업시간, 체크인 마감, 막차, 편의점/마트 위치를 먼저 확인한다.

## 6. 일반 체류일 루트
- 하루는 숙소에서 시작해 숙소로 끝난다.
- 핵심 권역은 1~2개, 핵심 목적지는 2~3개로 제한한다.
- 식당은 동선 중간에 배치하고, 대기가 긴 식당은 대체 후보를 가까이에 둔다.
- 쇼핑은 너무 이른 시간보다 매장 영업시간, 택스프리, 짐 증가 후 귀가 동선을 고려해 오후/저녁에 배치한다.
- 밤 일정 후 숙소 복귀 수단과 막차를 확인한다.

## 7. 숙소 이동일 루트
- 체크아웃 시간, 짐 보관, 다음 숙소 체크인 시간을 먼저 배치한다.
- 숙소 간 이동이 길면 관광은 중간 경유지 1개 또는 목적지 도착 후 가벼운 일정으로 줄인다.
- 서로 다른 도시로 이동하면 역/공항 접근과 도착 후 숙소 이동을 하루의 핵심 일정으로 본다.
- 짐을 들고 맛집 대기, 계단 많은 관광지, 혼잡한 시장을 넣지 않는다.

## 8. 불가능 일정 신호
- 이동과 대기만으로 하루 절반 이상이 사라진다.
- 점심/저녁 시간이 계속 밀린다.
- 짐을 가진 상태로 장거리 도보나 혼잡지 이동이 반복된다.
- 공항/역 도착 버퍼가 너무 짧다.
- 마지막 활동 장소에서 숙소나 공항까지 돌아가는 교통이 약하다.
- 우천/폭염/한파인데 야외 대기와 도보가 많다.

불가능 신호가 있으면 일정을 강행하지 말고 축소안과 대체안을 제시한다.

## 9. 현지 루트 지도 검증
사용자가 "이 동선이 최적인지 보고 싶다", "지도에서 루트로 보고 싶다", "숙소와 관광지를 어떻게 도는 게 좋은지 봐줘"처럼 말하면 전체 여행 체인과 별도로 **현지 루트 검증**을 작성한다.

- 기본 검증 범위는 목적지 공항/역/항구 도착 이후부터다. 집에서 출국 공항·역·항구까지 가는 구간은 사용자가 요청하지 않으면 지도 루트 검증에서 제외한다.
- 전체 일정 문서에는 집 출발과 귀가 흐름을 유지하되, 지도/HTML 루트 화면은 현지 이동만 별도 표시할 수 있다.
- 첫날은 `목적지 공항/역/항구 -> 숙소 또는 첫 방문지 -> 숙소`를 기준으로 본다.
- 체류일은 `숙소 -> 관광지/식당/카페/쇼핑 -> 숙소`를 기준으로 본다.
- 숙소 이동일은 `이전 숙소 -> 중간 경유지 또는 역/터미널 -> 다음 숙소`를 기준으로 본다.
- 마지막 날은 `숙소 -> 마지막 식사/쇼핑/관광 -> 목적지 공항/역/항구`를 기준으로 본다.

개별 장소 지도 링크만 나열하지 말고 Day별 길찾기 링크를 우선 제공한다.

```text
Google Maps Directions:
https://www.google.com/maps/dir/?api=1&origin=[출발지]&destination=[도착지]&waypoints=[경유지1|경유지2]&travelmode=[driving|walking|transit]
```

- 장소명은 가능한 공식 명칭과 도시명을 함께 넣는다.
- URL에는 인코딩된 장소명을 사용한다.
- 좌표나 정확한 지명이 확인되지 않았으면 임의 좌표를 쓰지 말고 지도 검색 링크와 `정확 위치 확인 필요`를 표시한다.
- Google Maps가 현지 대중교통을 완전히 지원하지 않는 지역은 현지 지도, 버스/철도 공식 앱, 택시 예상 시간을 함께 확인한다.

## 10. 루트 최적성 판단
최적 루트는 최단거리만으로 정하지 않는다. 아래 기준으로 2~3개 방문 순서를 비교한 뒤 추천 순서를 고른다.

| 판단 기준 | 확인 내용 |
|---|---|
| 방향성 | 같은 권역을 묶고 되돌아가는 이동을 줄였는가 |
| 이동수단 적합성 | 도보, 대중교통, 택시, 렌터카 중 실제로 쓰기 좋은가 |
| 짐 상태 | 캐리어를 든 상태로 계단, 혼잡지, 긴 도보가 생기지 않는가 |
| 시간 제약 | 체크인, 영업시간, 예약 시간, 막차와 충돌하지 않는가 |
| 식사 리듬 | 점심/저녁 시간이 자연스럽고 대체 식당이 가까운가 |
| 날씨와 피로도 | 우천, 폭염, 야간 안전, 동행자 체력에 무리가 없는가 |
| 비용 영향 | 택시나 유료 교통이 과도하게 늘지 않는가 |

권장 표기는 아래처럼 한다.

- `추천`: 이동 방향, 시간 제약, 짐 처리, 식사 리듬이 모두 무난하다.
- `조건부`: 특정 이동수단, 예약 시간, 날씨 조건이면 가능하다.
- `비추천`: 되돌아가기, 짐 부담, 영업시간 충돌, 막차 리스크가 크다.

예상 이동시간은 지도 조회값과 실제 여행 버퍼를 구분한다. 실시간 조회가 없으면 `지도 확인 필요`를 붙이고, 대중교통 기준과 택시 대체 시간을 나눠 적는다.
