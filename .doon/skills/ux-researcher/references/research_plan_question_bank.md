## 2. 질문 은행

### 최근 행동

- 마지막으로 이 문제를 겪은 때는 언제였나요?
- 그때 어떤 순서로 해결하려고 했나요?
- 어떤 도구나 사람에게 의존했나요?
- 해결하는 데 가장 오래 걸린 부분은 무엇이었나요?

### 동기와 비용

- 이 문제가 해결되지 않으면 어떤 영향이 있나요?
- 지금 방식에서 가장 불편하지만 참고 있는 부분은 무엇인가요?
- 돈, 시간, 실수, 불안 중 어떤 비용이 가장 큰가요?

### 기존 대안

- 지금은 어떤 방식으로 대신 해결하나요?
- 그 대안에서 계속 쓰고 싶은 점은 무엇인가요?
- 바꾸기 어렵게 만드는 이유는 무엇인가요?

### 성공 기준

- “잘 해결됐다”고 느끼려면 무엇이 달라져야 하나요?
- 처음 써본 뒤 계속 쓸지 판단하는 기준은 무엇인가요?
- 이 기능을 다른 사람에게 추천하려면 어떤 조건이 필요할까요?

## 3. 피해야 할 질문

| 피할 질문 | 문제 | 대체 질문 |
|---|---|---|
| 이 기능 좋죠? | 답을 유도함 | 어떤 상황에서 이 기능을 쓸 것 같나요? |
| 이걸 쓰시겠어요? | 실제 행동과 다를 수 있음 | 최근 비슷한 문제를 어떻게 해결했나요? |
| 얼마를 내겠어요? | 맥락 없는 가격 질문 | 지금 대안에 드는 시간/비용은 어느 정도인가요? |
| 불편한 점이 있나요? | 너무 넓음 | 마지막 작업에서 막힌 순간을 말해 주세요. |

## 4. 사용성 테스트 과제

| 과제 | 시작 조건 | 성공 기준 | 관찰 포인트 | 실패 신호 |
|---|---|---|---|---|
|  |  | 사용자가 도움 없이 완료 | 망설임, 되돌아감, 오입력 | 포기, 잘못된 경로 |

작성 기준:

- 과제는 “버튼을 누르세요”가 아니라 사용자가 달성할 목표로 쓴다.
- 테스트 중에는 먼저 설명하지 않고 관찰한다.
- 완료 시간보다 어디서 왜 막혔는지를 우선 본다.
