# Acceptance Criteria Matrix

요구사항을 개발, 디자인, QA가 같은 기준으로 검증해야 할 때 사용한다. PRD, 기능 명세, QA 체크리스트를 만들 때 읽는다.

## 1. 요구사항 기본 표

| ID | 사용자 | 목표 | 전제 조건 | 요구사항 | 우선순위 | 상태 | 출처 |
|---|---|---|---|---|---|---|---|
| FR-001 |  |  |  |  | must/should/could | draft/active/deferred |  |

상태 기준:

- `draft`: 아직 사용자 확인이나 정책 판단이 필요하다.
- `active`: 구현과 QA 기준으로 사용할 수 있다.
- `deferred`: 이번 범위에서 제외하지만 이유를 남긴다.

## 6. PRD 완성도 점검

- 문제, 사용자, non-goals, release criteria가 요구사항과 연결되어 있는가?
- 핵심 요구사항마다 acceptance criteria가 있는가?
- 정책과 구현 제약이 요구사항 문장 안에 섞여 있지 않은가?
- 미정 항목이 구현자에게 숨은 의사결정으로 넘어가지 않는가?
- 변경되면 문서, QA, 운영 공지가 필요한 항목이 표시되어 있는가?
