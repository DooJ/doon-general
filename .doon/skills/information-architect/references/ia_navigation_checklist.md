# IA And Navigation Checklist

화면 목록, 메뉴 구조, 콘텐츠 그룹, 검색/필터 기준을 정할 때 사용한다. 복잡한 기능을 화면 구조로 정리하거나 기존 IA를 재정비할 때 읽는다.

## 1. 인벤토리

| 항목 | 유형 | 사용자 목표 | 사용 빈도 | 권한 | 데이터 원천 | 현재 위치 | 후보 위치 |
|---|---|---|---|---|---|---|---|
|  | 기능/콘텐츠/설정/운영 |  | high/medium/low |  |  |  |  |

분류 기준:

- 기능: 사용자가 행동을 완료하기 위해 조작하는 것
- 콘텐츠: 사용자가 읽고 판단하는 정보
- 설정: 제품 동작이나 개인화를 바꾸는 것
- 운영: 관리자나 내부 사용자가 관리하는 것

## 2. 화면 책임

| 화면 | 주요 사용자 | 목적 | 핵심 정보 | 핵심 행동 | 진입 경로 | 이탈/다음 경로 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

점검:

- 한 화면에 서로 다른 1순위 행동이 둘 이상이면 분리나 hierarchy 조정 후보로 본다.
- 화면명은 내부 기능명보다 사용자가 기대하는 결과를 드러내게 쓴다.
- 운영자 화면과 일반 사용자 화면을 같은 navigation 모델로 묶어도 되는지 확인한다.

## 3. Navigation 모델 선택

| 모델 | 잘 맞는 경우 | 주의할 점 |
|---|---|---|
| Top nav | 영역이 적고 전환이 명확함 | 항목이 늘면 금방 복잡해짐 |
| Side nav | 관리자, SaaS, 반복 업무 | 깊이가 늘면 현재 위치 표시가 중요함 |
| Bottom tab | 모바일 핵심 영역 3-5개 | 보조 기능을 억지로 넣지 않음 |
| Stepper | 순서가 중요한 작업 | 자유 이동이 필요한 업무에는 답답함 |
| Dashboard hub | 여러 지표와 작업 진입점 | 단순 링크 모음으로 만들지 않음 |
| Search/command 중심 | 항목이 많고 숙련 사용자가 많음 | 신규 사용자를 위한 browse 경로가 필요함 |

## 4. 검색, 필터, 정렬

| 대상 | 검색 필드 | 필터 | 정렬 | 기본값 | 저장 여부 | 빈 결과 처리 |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

체크 항목:

- 필터는 사용자의 의사결정 기준과 일치해야 한다.
- 기본 정렬은 가장 자주 필요한 판단을 먼저 보여줘야 한다.
- 빈 결과는 필터 해제, 새 항목 생성, 권한 확인 중 어떤 행동으로 이어질지 정한다.

|  |  |  |  |  |

## 6. IA 검증 질문

- 1순위 작업까지 3단계 안에 도달하는가?
- 사용자가 현재 위치와 다음 행동을 알 수 있는가?
- 같은 정보가 여러 위치에 중복되어 다른 해석을 만들지 않는가?
- 새 화면을 추가하지 않고 grouping, tab, filter로 해결할 수 있는가?
- 모바일이나 좁은 화면에서 navigation 모델이 깨지지 않는가?
