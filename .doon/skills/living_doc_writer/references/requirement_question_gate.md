# 문서 질문 게이트
문서를 쓰기 전에 아래 항목을 확인한다. 중요한 선택을 임의로 정하면 요구사항 정의서, 기술 설계서, 일정, QA뿐 아니라 운영, 보안, 사용자 가이드, 온보딩 문서도 모두 흔들린다.

## 질문이 필요한 경우
- 선택지에 따라 POC 필요 여부, MVP 범위, PRD 작성 범위가 달라진다.
- 선택지에 따라 화면 수, 권한, 데이터 모델, API, 비용, 일정이 달라진다.
- 사용자가 원하는 제품 성격을 여러 방향으로 해석할 수 있다.
- 디자인 방향이나 플랫폼이 정해지지 않아 화면 명세를 확정할 수 없다.
- 개인정보, 결제, 외부 API, 관리자 기능처럼 리스크가 큰 기능이 암시되어 있다.
- 운영 주체, 배포 환경, 장애 대응 책임이 정해지지 않았는데 운영 문서를 요청했다.
- 사용자에게 공개할 문서인지 내부 문서인지 불명확하다.
- 데이터 보존, 삭제, 권한, 개인정보 처리처럼 정책 판단이 필요한 항목이 있다.
- KPI, 이벤트, 가격처럼 비즈니스 해석이 달라지는 항목이 있다.

## 질문 방식
- 한 번에 핵심 5개 안팎으로 묻는다.
- 각 질문에는 가능한 선택지 2-3개와 추천안을 함께 제시한다.
- 사용자가 답하지 않아도 진행 가능한 항목은 `가정`으로 문서화한다.
- 답이 없으면 위험한 항목은 문서 생성을 멈추고 먼저 확인한다.
- 질문 뒤에는 "답변을 받으면 요구사항 정의서와 후속 문서에 반영하겠다"처럼 다음 행동을 명확히 한다.

## 우선 질문 목록
| 영역 | 반드시 확인할 내용 | 예시 선택지 |
|---|---|---|
| 제품 목적 | 해결하려는 문제와 성공 기준 | 매출, 사용 시간, 업무 시간 절감, 오류 감소 |
| 대상 사용자 | 1순위 사용자와 보조 사용자 | 일반 사용자, 관리자, 운영자, 파트너 |
| 플랫폼 | 어디서 사용할지 | 웹, 모바일 웹, Android, iOS, 데스크톱, 내부 관리자 |
| POC 필요 여부 | 먼저 검증할 가장 위험한 가설이 있는지 | 기술 가능성, 사용자 수요, 데이터 수집 가능성 |
| MVP 범위 | 이번 버전에 반드시 넣을 기능 | 핵심 1개 기능, 가입/로그인 포함, 관리자 포함 |
| PRD 상태 | 지금 PRD를 확정할지, 초안/지연으로 둘지 | active, draft, deferred |
| 제외 범위 | 이번 버전에서 하지 않을 것 | 결제 제외, 알림 제외, 소셜 로그인 제외 |
| 인증/권한 | 계정과 역할이 필요한지 | 비로그인, 일반 로그인, 역할 기반 권한 |
| 데이터 | 저장할 핵심 데이터와 민감도 | 개인 정보 없음, 기본 프로필, 결제/위치/건강 정보 |
| 외부 연동 | 연결할 서비스나 API | 없음, 결제, 지도, 알림, OpenAI, 사내 시스템 |
| 디자인 방향 | 제품 인상과 정보 밀도 | 조용한 업무형, 소비자 앱형, 대시보드형 |
| 기술 제약 | 반드시 쓰거나 피할 기술 | 기존 스택 유지, 빠른 MVP 우선, 확장성 우선 |
| 배포/운영 | 운영 환경과 릴리즈 방식 | 로컬, 사내 서버, 클라우드, 앱스토어 |
| 운영 책임 | 누가 운영하고 장애를 처리할지 | 개발자, 운영자, 사내 관리자, 외부 고객지원 |
| 문서 공개 범위 | 내부용인지 사용자 공개용인지 | 내부 전용, 관리자용, 최종 사용자 공개 |
| 보안/개인정보 | 확인이 필요한 정책과 민감정보 | 계정 정보, 결제 정보, 위치/건강 정보, 로그 마스킹 |
| 데이터 보존 | 보관과 삭제 기준 | 즉시 삭제, 기간 보관, 백업 보관, 사용자 요청 삭제 |
| 성과 측정 | 성공을 판단할 지표 | 가입, 전환, 재방문, 업무 시간 절감, 오류 감소 |
| 일정 | 필요한 마감과 단계 | 1주 프로토타입, 1개월 MVP, 단계별 릴리즈 |
| QA | 출시 전 검수 범위 | 핵심 흐름만, 브라우저/기기별, 권한/보안 포함 |

## 질문 예시
아래처럼 묻는다.

```markdown
요구사항 정의 전에 세 가지가 갈립니다.

- 플랫폼은 웹 MVP로 시작할까요, 모바일 앱까지 포함할까요? 추천은 웹 MVP입니다. 화면/배포/QA 범위가 가장 작습니다.
- 로그인은 1차 버전에 포함할까요? 추천은 역할이나 개인화가 필요할 때만 포함입니다.
- 관리자 화면이 필요할까요? 운영자가 데이터를 직접 수정해야 하면 포함하고, 아니면 2차로 미루는 편이 낫습니다.
```

## 질문 없이 진행 가능한 경우
- 사용자가 이미 플랫폼, 사용자, MVP, 핵심 화면, 기술 제약을 제공했다.
- 선택지가 있어도 후속 문서에서 `미정`으로 남겨도 구현 착수에 큰 문제가 없다.
- 사용자가 "가정해서 초안부터 만들어줘"라고 명시했다. 이 경우 모든 가정을 문서 상단에 모은다.
