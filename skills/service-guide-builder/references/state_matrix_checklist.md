# State Matrix Checklist

가이드가 실제 제품 설명으로 쓸 수 있으려면 정상 화면만 있으면 부족하다. 아래는 탐색 후보이며 모든 상태를 강제하지 않는다. 실제 코드·실행 화면에 존재하고 요청 범위에 필요한 상태만 화면 목록에 연결한다.

## 공통 상태

- 기본 상태
- 로딩 중
- 빈 데이터
- 일부 완료
- 전체 완료
- 오류
- 권한 없음
- 입력값 오류
- 외부 서비스 미연결
- 네트워크 실패
- 저장 실패
- 취소 또는 중단

## UI 모드

- 보기 모드
- 수정 모드
- 잠금/해제
- 쉬운 모드/전문가 모드
- 목록/그리드
- 선택 없음/단일 선택/다중 선택
- 데스크톱/모바일/태블릿
- 가로/세로
- 밝은 배경/어두운 배경

## 운영/장비 서비스 상태

- 장비 연결 전/연결 중/연결 완료
- Bluetooth, Wi-Fi, Ethernet, MQTT 같은 연결 타입별 상태
- 로컬 fallback
- 파일 없음/파일 있음/지원하지 않는 파일
- 설정 보기/편집/저장 실패
- 토스트, 다이얼로그, 오버레이, 상태 메시지

## 다국어 상태

- 실제 지원 언어 목록
- 화면 문구 전환
- 설명 패널 전환
- placeholder/value/aria-label 전환
- 긴 번역문에서 레이아웃 깨짐 여부

## 검증 질문

- 각 상태가 실제 코드, 캡쳐, 로그, mock 데이터 중 무엇을 근거로 하는가?
- 실제 구현되지 않은 상태를 가이드에 보여줘야 한다면 라벨을 붙였는가?
- 이전/다음 순서가 상태 화면까지 빠짐없이 지나가는가?
- 상태 전환 후 강조 박스와 상세 패널이 여전히 같은 대상을 가리키는가?
