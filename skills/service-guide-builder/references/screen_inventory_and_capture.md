# 실제 화면 목록과 캡처

이 문서는 가이드 화면을 만들기 전에 사용한다. 소스 파일 이름만 나열하는 것이 아니라 **사용자가 도달하는 화면**과 그 화면의 실제 모습·상태를 확인한다.

## 1. 진입점 찾기

- 실행 문서와 빌드 설정에서 웹·앱·장비 화면을 여는 방법을 확인한다.
- 라우트·내비게이션·메뉴·딥링크·Activity/Fragment·SwiftUI navigation·화면 컴포넌트에서 진입 가능한 화면을 찾는다.
- 역할·권한, 로그인 여부, 기능 플래그, 연결 장비, 데이터 유무가 화면을 바꾸는지 확인한다.
- UI 코드뿐 아니라 문자열 리소스, 이미지·아이콘, 디자인 토큰과 실제 화면 캡처를 연결한다.

파일 검색은 프로젝트 언어와 구조에 맞춘다. 예를 들어 `rg --files`로 라우트·화면 파일을 찾고, `rg`로 메뉴 항목·버튼 문구·핸들러·상태 키를 추적한다. 파일명만으로 화면 존재나 노출을 확정하지 않는다.

## 2. 화면 목록

| 화면 ID | 사용자 진입 경로 | 역할·플랫폼 | 실제 확인 상태 | UI·문구 근거 | 캡처·확인 시점 | 미확인 사항 |
|---|---|---|---|---|---|---|
| 예: settings-account | 설정 → 계정 | 로그인 사용자·모바일 | 기본·저장 오류 | 라우트, 화면 컴포넌트, 문자열 파일 | 캡처 경로·날짜 | 관리자 권한 상태 |

화면 ID는 가이드 메뉴, 중앙 화면, 설명 데이터에 공통으로 사용한다. 같은 라우트라도 역할이나 모드에 따라 구성이 크게 달라지면 화면 또는 상태를 분리한다. 사용자가 요구한 범위에 없는 화면을 숫자 채우기용으로 넣지 않는다.

## 3. 실제 실행과 캡처

실행 환경이 있으면 제품을 열어 메뉴에서 실제로 이동하고 요청된 화면을 캡처한다. 정상 화면만 보지 말고 가이드에서 설명할 팝업, 스크롤 아래의 조작, 비활성 버튼, 빈 목록, 오류와 권한 상태를 해당 조건으로 확인한다. 화면마다 viewport/해상도, 언어, 역할, 데이터·연결 상태, 제품 버전 또는 확인 날짜를 기록한다. 저장·전송·결제·삭제처럼 실제 상태를 바꾸는 흐름은 허가된 테스트 환경이나 제공된 기록으로 확인하고, 화면 조사를 이유로 운영 데이터를 변경하지 않는다.

실행에 로그인·장비·테스트 데이터가 필요한데 사용할 수 없다면 코드와 제공된 캡처로 확인 가능한 부분을 먼저 매핑한다. 실행 미확인 부분은 분명히 표시하고, 필요한 접근이나 화면 자료를 요청한다. 임의의 계정·가상 데이터로 실제 제품 상태를 가장하지 않는다.

## 4. 누락 확인

- 요청된 화면·기능 목록과 발견한 화면 목록을 대조한다.
- 메뉴에는 있으나 중앙 화면이 같은 채로 남는 항목이 없는지 확인한다.
- 화면마다 주요 조작 요소가 보이는 상태와 숨겨지는 상태를 구분한다.
- 코드·캡처·실행 화면이 충돌하면 시각 배치는 최신 실행 캡처를 우선하고, 동작은 실행 결과와 코드로 재확인한다. 충돌 원인과 적용 기준을 남긴다.
- 확인하지 못한 화면은 가이드에서 실제 화면처럼 그리지 않는다. 필요하면 빈 자리와 ‘자료 미확인’ 표시를 두고 완료 범위에서 제외한다.
