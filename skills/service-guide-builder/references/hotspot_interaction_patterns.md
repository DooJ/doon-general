# 화면 요소와 설명 연결 방식

핫스팟은 기능을 발명하는 수단이 아니라 근거표에서 확인한 조작 위치를 설명 패널에 연결하는 수단이다. 화면과 상태가 바뀌면 현재 보이는 대상만 연결한다.

## DOM 또는 실제 컴포넌트 기반

1. 현재 `screen_id`·`state_id`에 해당하는 실제 UI 컴포넌트 또는 근거 있는 재현 화면을 렌더링한다.
2. 근거표의 조작 요소에 안정적인 `target_id`를 붙인다. 같은 화면·상태에서 중복 ID를 쓰지 않는다.
3. 설명 데이터도 같은 화면·상태·대상 ID를 사용한다. 화면을 바꿀 때 중앙 콘텐츠와 설명 데이터·선택 상태를 함께 전환한다.
4. 화면 렌더 후 대상 요소를 찾는다. 0개 또는 2개 이상이면 그 설명 포인트를 유효한 것으로 표시하지 말고 원인을 수정한다.
5. 장식용 강조 테두리는 `pointer-events: none`으로 두고 실제 설명 대상의 클릭·키보드 포커스를 막지 않는다. 가이드 모드에서는 조작 대신 설명을 열도록 처리할 수 있지만, 저장·결제·외부 호출이 일어나는 것처럼 가장하지 않는다.

```html
<button type="button" data-guide-target="save-profile">저장</button>
```

```js
const step = {
  screen_id: "settings-account",
  state_id: "editing",
  target_id: "save-profile",
  title: "저장",
  source: "settings/account.tsx · SaveButton → saveProfile",
};
```

앱 자체 컴포넌트를 재사용할 때 가이드 클릭이 실제 데이터를 바꾸는지 먼저 확인한다. 필요하면 읽기 전용 가이드 모드나 테스트 데이터를 사용하고, 동작을 막은 경우 실제 제품 동작과 구분한다.

## 실제 캡처 위에 설명을 놓을 때

화면 캡처의 원본 크기, 표시 크기, `object-fit`과 여백을 알아야 클릭 영역을 정확히 맞출 수 있다. 캡처에서 측정한 좌표를 원본 이미지 크기에 대한 비율로 저장하고, 렌더된 이미지 영역에 맞춰 다시 계산한다. 화면 비율이나 이미지가 달라지면 좌표를 검증·수정한다. 캡처에는 DOM 버튼이 없으므로 설명용 투명 버튼의 이름과 키보드 접근을 제공한다. 이 버튼은 가이드 조작임을 명확히 한다.

## 전환과 검증

- 이전/다음은 화면·상태·설명 포인트의 실제 순서를 따른다. 다음 화면으로 이동하면 중앙 화면과 대상이 함께 바뀐다.
- 팝업, 스크롤, 비활성/활성, 언어, 가로/세로 변경 뒤 대상 위치와 설명 내용이 일치하는지 다시 검사한다.
- 설명 데이터에 없는 요소를 자동으로 임의 설명하지 않는다. 코드에 없는 요소를 가이드용 버튼으로 추가하지 않는다.
- 모든 요청된 핵심 조작을 클릭·키보드로 선택해 예상한 설명이 열리는지 브라우저에서 확인한다. 존재하지 않는 대상, 중복 대상, 화면 밖 대상, 가려진 대상은 실패로 기록한다.
