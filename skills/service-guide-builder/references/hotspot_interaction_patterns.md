# Hotspot Interaction Patterns

가이드의 클릭 설명은 실제 페이지를 로드하는 것이 아니라, 실제 코드와 화면을 근거로 재현한 가이드 화면에 설명용 식별자를 붙이는 방식이 기본이다.

## 기본 패턴

1. 실제 UI 코드와 캡쳐를 확인한다.
2. 가이드용 화면을 HTML/React 등으로 재현한다.
3. 설명할 요소에 `data-guide-target`을 붙인다.
4. 설명 데이터의 `target`과 연결한다.
5. 사용자가 요소나 강조 박스를 클릭하면 우측 상세 패널을 갱신한다.

```html
<button class="primary" data-guide-target="new-job">
  새 작업 만들기
</button>
```

```js
const steps = [
  {
    target: "new-job",
    title: "새 작업 만들기",
    lead: "작업명 입력 모달을 열고 새 draft를 시작합니다.",
    sources: ["components/job-app.tsx · NewJobButton"],
  },
];
```

## 강조 박스

- 강조 박스는 실제 요소 위에 덮지만, 실제 요소 클릭을 막지 않게 한다.
- 고정 좌표보다 `data-guide-target` 요소의 `getBoundingClientRect()` 기준으로 위치를 계산한다.
- 화면 내부가 스크롤되면 강조 박스도 같은 레이어 안에서 움직이게 둔다.
- 강조 표시를 꺼도 현재 선택된 설명 포인트는 별도 active 상태로 남긴다.

## 이전/다음 흐름

이전/다음 버튼은 단순 화면 이동이 아니라 다음 순서를 하나로 연결한다.

```text
화면 1 개요
화면 1 핫스팟 1
화면 1 핫스팟 2
화면 2 개요
화면 2 핫스팟 1
```

사용자가 다음을 누르면 현재 화면 안의 설명 포인트를 먼저 넘기고, 마지막 포인트 이후 다음 화면으로 이동한다.

## 상세 패널 필드

각 설명 포인트는 다음 필드를 우선한다.

- 제목
- 사용자가 보는 내용
- 클릭/선택 시 동작
- 결과 상태
- 조건 또는 주의점
- 구현 근거: UI 파일, 동작 코드, 문자열 리소스, mock 데이터

## 피해야 할 패턴

- 실제 페이지를 로드하지 않았는데 실제 앱이 그대로 들어온 것처럼 설명하지 않는다.
- 임의 좌표만으로 핫스팟을 만든 뒤 화면 구조 변경을 방치하지 않는다.
- 강조 박스가 버튼 클릭, 스크롤, 포커스 이동을 막지 않게 한다.
- 설명 데이터에 source가 없으면 나중에 실제 코드 변경과 대조하기 어렵다.
