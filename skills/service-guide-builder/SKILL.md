# 실제 제품 기반 인터랙티브 서비스 가이드

사용자가 제품 화면을 보며 조작 위치와 결과를 이해할 수 있는 가이드를 만든다. 화면 수집, 기능 추적, 설명 연결, 브라우저 검증을 하나의 작업으로 취급한다. 코드·리소스·캡처·실행 결과로 확인하지 못한 기능을 실제 제품 기능처럼 채우지 않는다. 가이드용 재현 화면을 실제 제품 화면이나 실행 중인 앱으로 가장하지 않는다.

정적 사용 설명서·FAQ·운영 매뉴얼은 `living-doc-writer`의 범위다. 화면별 설명 요청만으로 웹 가이드 구현을 가정하지 않는다.

## 1. 대상과 범위 파악

- 대상 저장소·앱, 가이드 사용자(최종 사용자·운영자 등), 요청한 화면·기능·권한·플랫폼을 확인한다. 명시된 범위가 있으면 그대로 따른다.
- 화면 단위, 기능 단위, 혼합형 중 실제 탐색 목적에 맞는 구조를 정한다. 화면 단위는 버튼 위치 학습, 기능 단위는 여러 화면을 거치는 작업 수행, 혼합형은 두 목적이 모두 중요할 때 쓴다.
- 범위가 넓거나 애매하면 먼저 실제 화면과 기능 목록을 조사해 **구체적인 포함 목록과 산출물 형태**를 제시한다. 결정에 필요한 정보가 그 뒤에도 없을 때만 간결하게 묻는다. 사용자가 이미 범위를 정했거나 단일 화면·기능인 경우에는 작업을 진행한다.
- 정적 HTML, 앱 내부 가이드 라우트, 이동용 엔트리 중 산출물 형태를 정한다. 선택 기준은 `references/guide_output_patterns.md`에 있다.

## 2. 실제 화면을 수집해 목록 확정

가이드 레이아웃을 만들기 전에 `references/screen_inventory_and_capture.md`에 따라 화면 목록을 만든다. 라우트·내비게이션·Activity/Fragment/View/컴포넌트·권한·기능 플래그·언어 리소스에서 진입점을 찾고, 실제로 도달 가능한 화면과 상태를 대조한다.

화면마다 **화면 ID, 진입 경로, 대상 역할·플랫폼, 확인한 상태, UI 코드, 실제 캡처 또는 실행 확인, 미확인 항목**을 남긴다. 제품을 실행할 수 있으면 직접 탐색해 화면·팝업·스크롤·빈/오류 상태를 캡처한다. 실행할 수 없으면 코드에서 확인한 구조와 실제 화면의 시각적 모습이 미검증임을 표시하고, 필요한 캡처나 접근 정보를 요청한다. 코드에만 있는 미구현 화면이나 오래된 캡처를 현재 화면으로 단정하지 않는다.

화면 목록이 요청 범위를 덮는지 확인한다. 가이드의 화면 메뉴 이름만 다르게 만들고 중앙에 같은 화면을 재사용하지 않는다. 화면을 바꿀 때 중앙 콘텐츠와 설명 대상도 해당 화면·상태로 함께 바뀌어야 한다.

## 3. 조작 요소와 기능을 추적

`references/evidence_mapping_checklist.md`의 화면·상태·요소별 근거표를 만든다. 화면의 버튼, 탭, 메뉴, 입력, 카드 등 **실제로 보이고 사용자가 조작하는 요소**에서 시작해 핸들러·이동·상태 변화·API/저장 동작과 사용자에게 보이는 결과까지 추적한다. 비활성·권한 제한·미연결·외부 서비스 의존도 기록한다.

- 각 설명은 해당 화면·상태에서 보이는 대상 요소 하나에 연결한다. 화면 이름이나 버튼 문구가 비슷하다는 이유만으로 다른 기능을 연결하지 않는다.
- 클릭할 수 없는 정보 영역은 설명 주석으로 다루고, 존재하지 않는 버튼을 만들지 않는다. 동작 근거가 불명확하면 기능 설명을 추측하지 말고 미확인으로 남긴다.
- 설명 대상 중복·누락, 보이지 않는 대상, 잘못된 상태의 설명을 구현 전에 확인한다. 대상이 많으면 사용자의 핵심 작업과 화면상 주요 조작부터 연결한다.

## 4. 화면과 설명 연결 구현

실제 화면을 가장 정확하게 보여줄 수 있는 방식을 고른다. 기존 UI 컴포넌트를 안전하게 재사용할 수 있으면 가이드 모드로 재사용하고, 그렇지 않으면 실제 캡처 위에 설명 영역을 연결하거나 근거 있는 UI만 재현한다. 방식마다 실제 제품과 다른 부분을 표시한다. 캡처 기반 가이드는 이미지 크기·비율 변화에 맞춰 설명 위치를 다시 계산하고, 재현 UI는 실제 화면과 나란히 확인해 누락·배치 차이를 수정한다.

화면 ID·상태 ID·설명 대상 ID를 안정적으로 연결한다. `references/hotspot_interaction_patterns.md`의 규칙에 따라 클릭 대상과 설명 데이터가 일대일로 맞는지 검사한다. 화면 전환·팝업·상태 변경·언어 전환·크기 변경 뒤에도 현재 보이는 요소에 맞는 설명만 활성화한다. 강조 표시가 실제 조작을 가리거나 클릭을 빼앗지 않도록 한다.

설명에는 사용자가 보는 이름, 조작 조건, 수행 동작, 결과 또는 다음 화면, 미구현/오류 상태, 근거를 필요한 만큼 쓴다. 가이드에서 보여주는 시뮬레이션은 실제 서비스에 데이터를 저장하거나 외부 요청을 보내는 것처럼 표현하지 않는다.

## 5. 작동 검증과 인계

가이드를 브라우저에서 열어 **각 요청 화면이 실제로 다른 중앙 콘텐츠를 보여주는지**, 주요 조작 요소를 클릭했을 때 맞는 설명이 열리는지 확인한다. 메뉴·이전/다음·상태·언어 전환과 팝업 후에도 연결이 유지되는지 점검한다. 주요 화면 크기에서 설명 영역의 위치·가림·잘림, 키보드 접근, 콘솔 오류를 확인한다. 상태 점검은 `references/state_matrix_checklist.md`에서 실제 제품에 있는 항목만 선택한다.

완료 보고에는 요청한 화면/기능 수와 확인·연결한 수, 실행 확인 여부, 남은 미확인 화면·동작을 적는다. 요청 범위의 핵심 화면이나 클릭 대상이 빠졌으면 완료라고 말하지 않는다. 독립 가이드 폴더에는 `templates/guide_readme_template.md`를 따라 화면 목록, 제품 근거, 캡처 시점, 확인하지 못한 부분, 갱신 트리거와 검증 방법을 남긴다.

실제 앱 수정이 필요하다면 가이드 산출물과 변경 범위를 분명히 하고 요청에 포함된 수정만 수행한다. 예제 `examples/click-guide-sample/index.html`은 **가상 화면의 연결 방식만 보여준다**. 그 안의 화면·문구·기능을 실제 제품 근거로 사용하지 않는다.
