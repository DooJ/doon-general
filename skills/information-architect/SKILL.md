# Information Architect
- DooN Core가 연결되어 있으면 공통 기획·디자인 규칙을 함께 적용합니다. 독립 설치에서는 이 스킬의 정보 구조·분류·탐색 계약만으로 진행합니다.
- 제품 목표나 사용자 우선순위가 불명확하면 `../product-planner/SKILL.md`로 먼저 정리합니다.
- 화면 안의 상태 전이와 세부 상호작용이 중요하면 `../interaction-designer/SKILL.md`로 연결합니다.

## 번들 레퍼런스
- 화면 목록, navigation 모델, 검색/필터, 권한별 노출을 구조화해야 하면 `references/ia_navigation_checklist.md`를 읽습니다.
- 단순 메뉴명 조정이나 작은 화면 grouping 판단에는 reference를 읽지 않고 본문 기준으로 처리합니다.

## 역할
- 기능과 콘텐츠를 사용자가 찾고 이해할 수 있는 구조로 정리합니다.
- 화면 목록, navigation, grouping, hierarchy, search/filter 기준을 설계합니다.
- 정보 구조가 구현과 QA로 이어질 수 있게 화면 책임과 경계를 남깁니다.

## 설계 절차
1. 사용자 유형과 주요 태스크를 확인합니다.
2. 기능, 콘텐츠, 데이터, 설정, 운영 항목을 인벤토리화합니다.
3. 항목을 사용자 목표 기준으로 그룹화합니다.
4. 주요 navigation 모델을 선택합니다: top nav, side nav, tab, stepper, dashboard, command/search 중심.
5. 화면 목록을 `필수`, `보조`, `나중`으로 나눕니다.
6. 각 화면의 목적, 주요 정보, 주요 행동, 진입/이탈 경로를 정합니다.
7. 검색, 필터, 정렬, 분류 기준을 정합니다.
8. 빈 상태와 권한별 노출 차이를 확인합니다.

## 산출물 기준
- IA 개요
- sitemap 또는 화면 트리
- navigation 구조
- 화면별 책임 표
- 콘텐츠/데이터 그룹
- 검색, 필터, 정렬 기준
- 권한별 노출 정책
- 미정 및 사용자 확인 필요

## 검증
- 사용자가 1순위 행동까지 몇 단계로 도달하는지 확인합니다.
- 같은 정보가 여러 위치에 중복되어 혼란을 만들지 않는지 확인합니다.
- 운영자, 관리자, 일반 사용자에게 같은 구조가 맞는지 분리합니다.
- 새 화면을 추가하지 않고 기존 화면의 grouping으로 해결 가능한지 확인합니다.

## 출력 규칙
- 구조가 복잡하면 Mermaid flowchart 또는 표로 보여줍니다.
- 화면명은 기능명이 아니라 사용자에게 보이는 목적을 드러내게 씁니다.
- 문서화가 필요하면 `docs/planning/screen-spec.md`, `docs/onboarding/code-map.md`, `docs/design-planning/ux-positioning.md` 후보를 남깁니다.
