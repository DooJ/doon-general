# HTML 시각화 패턴
이 문서는 여행 HTML 시각화본을 만들 때 읽는다. 기존 마라도, 대마도, 타이베이 HTML은 별도 고정 템플릿 없이 `finalization_and_visual_outputs.md`의 구성 기준을 바탕으로 그때 만든 산출물이다. 앞으로는 이 문서와 `assets/html/day_route_visualization_sample.html`을 기준 샘플로 삼는다.

## 1. 기준 샘플
- 샘플 파일: `assets/html/day_route_visualization_sample.html`
- 샘플은 복사 후 여행지, 날짜, 동행 유형, 목적, 비용, Day 데이터만 교체해 사용한다.
- 외부 라이브러리 없이 열리는 단일 HTML을 기본값으로 둔다.
- 좌표와 지도 API가 확실하지 않으면 지도 타일을 넣지 말고 Day별 루트 카드와 Google Maps 길찾기 링크를 우선한다.

## 2. 공통 화면 구조
HTML은 아래 순서를 유지한다.

1. `hero`: 여행명, 단계, 기준 조회일, 핵심 전제, 주요 배지
2. `summary-grid`: 인원, 이동수단, 숙소 권역, 예산, 예약 상태 같은 빠른 요약
3. `decision-band`: MD 판단, 추천안, 주의점, 예약 전/후 상태
4. `tabs`: Day별 전환 버튼
5. `day-panel`: 각 Day의 루트 카드와 타임라인
6. `cost-section`: 확정/예상/선택 비용
7. `fallback-section`: 우천, 지연, 결항, 피로, 예약 실패 대체안
8. `checklist-section`: 예약, 준비물, 현지 확인, 비상정보

## 3. Day 패널 규칙
각 Day 패널은 지도보다 루트 판단을 먼저 보여준다.

- 왼쪽 또는 상단: `route-card`
  - Day 제목과 성격
  - `출발지 -> 경유지 -> 도착지` 노드 목록
  - Google Maps Directions 링크
  - 장소 검색 링크 또는 공식 링크
  - 최적성 판단: `추천`, `조건부`, `비추천`
  - 판단 이유: 방향성, 짐, 영업시간, 식사 리듬, 이동수단
- 오른쪽 또는 하단: `timeline`
  - 시간대
  - 활동명
  - 이동/활동/대기/버퍼
  - 예약 상태와 확인 필요 배지
  - 대체안

## 4. 현지 루트 기준
- 사용자가 현지 동선을 보고 싶다고 하면 집에서 출국 공항/역/항구까지의 접근 구간은 루트 카드에서 제외한다.
- Day 1은 목적지 공항/역/항구 또는 도착 항구에서 시작한다.
- 체류일은 숙소에서 시작해 숙소로 돌아오는 루프를 기본으로 한다.
- 마지막 날은 숙소에서 목적지 공항/역/항구까지의 흐름을 기본으로 한다.
- 전체 여정 문서에는 집 출발과 귀가를 남겨도, HTML의 Day별 루트 검증은 현지 이동만 별도 표시할 수 있다.

## 5. 데이터 작성 규칙
샘플의 `tripData`에 아래 필드를 채운다.

- `title`: HTML 제목과 hero 제목
- `eyebrow`: 여행 단계, 기준 조회일
- `subtitle`: 한 줄 요약
- `badges`: 여행 월, 박수, 동행 유형, 목적, 이동수단
- `theme`: 타이틀 이미지, 이미지 설명, 색상 변수, 오버레이
- `summary`: 상단 요약 카드
- `decision`: MD 판단 문장과 핵심 결정
- `days`: Day별 루트와 타임라인
- `costs`: 비용 요약
- `fallback`: 대체안
- `checklist`: 체크리스트

장소명은 공식 표기와 도시명을 함께 쓰고, Google Maps 링크는 `https://www.google.com/maps/dir/?api=1&origin=...&destination=...&waypoints=...&travelmode=...` 형식을 우선한다.

## 6. 타이틀 이미지와 색상 테마
HTML 타이틀 이미지는 나라 이름만 상징하는 국기형 이미지보다 실제 여행지의 첫인상을 보여주는 사진을 우선한다. 나라, 지역, 계절, 예상 날씨, 여행 목적을 함께 반영한다.

### 6.1 이미지 선택
- 특정 도시/섬/권역이 정해졌으면 그 장소의 실제 풍경, 랜드마크, 항구, 거리, 시장, 자연 이미지를 우선한다.
- 정확한 장소 이미지를 찾기 어렵다면 같은 지역권의 대표 풍경을 쓰되 `정확 이미지 확인 필요` 메모를 남긴다.
- 식도락 여행이면 시장, 음식 거리, 야시장, 항구 식당 같은 장면을 우선한다.
- 가족여행이면 이동과 안전을 해치지 않는 밝고 안정적인 도시/공원/숙소권 이미지를 우선한다.
- 휴양형이면 바다, 리조트, 숲, 온천처럼 체류감을 보여주는 이미지를 우선한다.
- 우천/장마/태풍 가능성이 큰 여행은 흐린 하늘 이미지만 쓰지 말고 실내 명소, 카페, 시장, 야경처럼 대체 가능한 분위기를 함께 살린다.
- 어둡고 흐릿한 stock 이미지, 과도하게 크롭된 사진, 실제 장소를 알아보기 어려운 추상 이미지는 피한다.
- 외부 이미지를 쓰면 접근 가능한 URL을 `theme.heroImage`에 넣고, 이미지 설명을 `theme.heroImageAlt`에 적는다.

### 6.2 계절/날씨 팔레트
아래를 출발점으로 삼고, 국가/도시의 실제 분위기에 맞춰 조정한다.

| 조건 | 권장 이미지 톤 | 권장 색상 방향 |
|---|---|---|
| 봄 | 꽃, 신록, 강변, 산책로 | 연한 초록, 부드러운 분홍, 밝은 회백 |
| 여름 | 바다, 항구, 숲, 야시장 | 청록, 바다색, 산뜻한 노랑, 흰색 |
| 가을 | 단풍, 오래된 거리, 시장, 노을 | 녹슨 주황, 올리브, 따뜻한 회색 |
| 겨울 | 눈, 온천, 야경, 실내 명소 | 남색, 차가운 회색, 아이보리, 포인트 빨강 |
| 우천/장마 | 실내 명소, 카페, 시장, 야경 | 짙은 초록, 먹색, 낮은 채도의 파랑 |
| 폭염 | 그늘, 바다, 실내 쇼핑, 카페 | 밝은 배경, 시원한 파랑/청록, 높은 대비 |
| 섬/해안 | 항구, 해변, 등대, 해산물 시장 | 바다색, 모래색, 흰색, 짙은 녹색 |
| 도시/쇼핑 | 거리, 역, 야경, 상점가 | 차콜, 선명한 포인트색, 밝은 표면색 |

### 6.3 지역 감도
- 한국 섬/해안: 현무암, 바다, 항구, 바람을 떠올리는 청록/먹색/아이보리 조합을 우선한다.
- 일본 소도시/섬: 항구, 숲, 온천, 로컬 상점가에 맞춰 남색, 삼나무색, 따뜻한 흰색을 쓴다.
- 대만 도시/근교: 야시장, 사원, 차 문화, 산지를 반영해 옥색, 따뜻한 빨강, 차콜, 아이보리를 조합한다.
- 동남아 휴양지: 열대 녹색, 바다색, 산호색을 쓰되 과한 채도는 줄인다.
- 유럽 도시: 석재, 강변, 광장, 계절색을 반영하고 한 가지 갈색/베이지로만 몰지 않는다.

### 6.4 적용 방식
샘플 HTML에서는 `tripData.theme`으로 아래 값을 채운다.

```javascript
theme: {
  heroImage: "https://...",
  heroImageAlt: "여행지와 계절을 설명하는 짧은 문장",
  overlayStart: "rgba(20, 34, 31, 0.12)",
  overlayEnd: "rgba(20, 34, 31, 0.82)",
  colors: {
    bg: "#f6f7f4",
    surface: "#ffffff",
    surfaceSoft: "#eef3ef",
    ink: "#1d2521",
    muted: "#66726d",
    line: "#d8ded9",
    accent: "#1f7a63",
    accent2: "#295c9f",
    warn: "#a86500",
    danger: "#a23b35"
  }
}
```

상태색인 `warn`, `danger`는 의미 전달이 우선이므로 테마에 맞춘다고 과도하게 바꾸지 않는다. 대비가 낮아지면 색보다 가독성을 우선한다.

## 7. UI 품질 기준
- 모바일에서 Day 탭, 루트 요약, 타임라인 순서로 잘 읽혀야 한다.
- 지도/루트 카드와 타임라인을 같은 Day 안에서 함께 보여준다.
- 배지는 예약 상태, 확인 필요, 추천, 조건부, 음식, 대체안을 구분하는 데만 쓴다.
- 카드 안에 또 다른 큰 카드를 중첩하지 않는다.
- hero는 정보 확인을 방해하지 않게 낮은 높이로 두고, 다음 요약 영역이 첫 화면에 일부 보이게 한다.
- 색상은 나라/지역/계절/날씨를 반영하되, 한 가지 색 계열만 반복하지 말고 중립 배경과 상태색을 분리한다.
- 정확하지 않은 지도 좌표, 임의 경로선, 과한 애니메이션은 넣지 않는다.

## 8. 기존 산출물에서 추출한 공통점
- `publish/travel/대한민국/마라도_3박4일_커플2쌍_식도락_시각화.html`: 결항 대체안, 배/항공/렌터카 확인 항목이 잘 드러난다.
- `publish/travel/일본/대마도_3박4일_커플2쌍_식도락_시각화.html`: Google Maps Directions 링크와 Day별 루트 패널 구조가 가장 재사용하기 좋다.
- `publish/travel/대만/타이베이_3박4일_가족여행_시각화.html`: 가족여행의 동행자 배려, 전용차/택시 판단, 예약 우선순위가 잘 드러난다.
