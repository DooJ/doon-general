# 문서별 품질 기준
문서가 많아도 내용이 얇으면 실패다. 각 문서는 개발, 디자인, QA, 인수인계 중 하나 이상의 실제 행동으로 이어져야 한다.

## 공통 필수 섹션
모든 주요 문서는 아래 요소를 포함한다.

- 목적
- 범위
- 근거 자료
- 확정 사항
- 가정
- 미정 및 사용자 확인 필요
- 관련 문서 또는 관련 코드
- 갱신 트리거
- 검증 방법

## 프로젝트 정의서

- 목표 사용자
- 핵심 가치 제안

- MVP 범위

- 제외 범위
- 주요 리스크
- 의사결정이 필요한 항목

## 얇은 문서 방지 규칙
- 제목과 일반론만 있는 문서는 만들지 않는다.
- "추후 작성"만 반복하지 않는다. 모르면 `미정`에 이유와 필요한 결정을 적는다.
- 같은 내용을 여러 문서에 복사하지 않는다. 문서별 책임을 나누고 관련 문서로 연결한다.
- 확정되지 않은 기능을 확정 요구사항처럼 쓰지 않는다.
- QA 문서는 요구사항과 화면 명세를 실제로 검증할 수 있어야 한다.

개발 착수 상세 절차와 항목 선택은 [개발 착수 문서 패키지](planning_document_package.md)를 따른다. 문서 수·특정 DB 엔진·HTML/Figma 도구를 모든 프로젝트에 강제하지 않고 같은 개발 판단에 필요한 정보를 기존 문서에 통합할 수 있다.
