# 스냅샷 보고서 작성기

- 보고서 본문은 한국어로 작성합니다. 코드 식별자, API 이름, 파일 경로, 명령어, 로그, 외부 고유명사는 원문을 유지할 수 있지만 해설과 요약은 한국어로 둡니다.
- 보고 대상이 비즈니스 이해관계자인지 개발팀인지 먼저 판단하고, 어휘와 깊이를 거기에 맞춥니다.
- 작성 전에는 코드베이스에서 사실을 검증합니다. 이슈, 흐름, 히스토리를 지어내지 않습니다.
- 제안이나 리팩토링 의견은 단일 해법처럼 단정하지 말고, 대안과 선택 기준, 검증 가능한 성공 조건을 함께 둡니다.
- 보고 범위가 부분 리포트인지 전체 리포트인지 먼저 구분합니다. 애매하면 `references/report_scope_router.md`를 읽습니다.
- 리빙독으로 반영할 수 있는 결론이 있으면 `references/report_living_doc_bridge.md`를 읽고 보고서 마지막에 반영 후보를 정리합니다.

## 프리앰블

- 보고 범위가 `부분 리포트`, `전체 리포트` 중 무엇인지 먼저 분류합니다.
- 보고서 유형이 `프로세스 분석`, `트러블슈팅`, `포스트모템`, `제안서`, `아키텍처 딥다이브`, `ADR`, `준비도 평가`, `리스크 리뷰` 중 무엇인지 분류합니다.
- 출력 디렉터리는 사용자 지정 경로가 있으면 그것을 사용하고, 없으면 기존 `results/`를 우선 사용하며, 둘 다 없으면 `reports/`를 기본값으로 삼습니다.
- 이 문서가 상시 유지 문서가 아니라 특정 시점의 스냅샷이라는 점을 명확히 합니다.
- 보고서 기준일, 분석 범위, 사용한 코드/로그/자료의 버전 또는 커밋을 확인 가능한 수준으로 남깁니다.
- 넓은 리포트 요청이면 `references/report_scope_router.md`와 `references/snapshot_report_package_matrix.md`를 읽고 보고서 세트를 정합니다.

## 작업 절차

1. 보고 범위가 부분인지 전체인지 정합니다.
2. 보고서 유형이 프로세스 분석, 트러블슈팅, 포스트모템, ADR, 제안서, 준비도 평가, 리스크 리뷰 중 무엇인지 정합니다.
3. `references/snapshot_report_package_matrix.md` 기준으로 필요한 단일 보고서 또는 보고서 세트를 정합니다.
4. 관련 코드, 로그, 설정, 기존 문서, 하네스 산출물을 먼저 확인합니다.
5. 선택한 출력 디렉터리 아래에 `<YYYYMMDD>_<topic>.md` 형식의 새 파일을 생성합니다.
6. 보고서는 특정 시점의 스냅샷으로 작성합니다. 상시 문서처럼 덮어쓰기 대상으로 취급하지 않습니다.
7. 의사결정이나 제안이 포함되면 대안, 선택 기준, 예상 효과, 비용, 되돌림 전략을 함께 적습니다.
8. `references/report_living_doc_bridge.md` 기준으로 `Living Docs 반영 후보` 섹션을 작성합니다. 반영할 결론이 없으면 없다고 명시합니다.

## 검증

- 사실, 추론, 권장 조치를 명확히 분리합니다.
- 기대 효과와 트레이드오프가 있는 제안이라면 둘 다 빠짐없이 적습니다.
- 숫자, 성능, 비용, 일정, 사용자 영향처럼 의사결정에 쓰이는 값은 출처 또는 계산 근거를 남깁니다.
- 권장 조치가 요청 범위를 넘어선다면 왜 필요한지와 하지 않았을 때의 리스크를 분리해서 적습니다.
- 보고서가 행동으로 이어져야 한다면 owner, next action, 검증 지표를 제안합니다.
- 전체 리포트를 요청받았으면 특정 기능 하나만 분석하고 끝내지 않았는지 확인합니다.
- 부분 리포트를 요청받았으면 프로젝트 전체 문서 세트를 불필요하게 만들지 않았는지 확인합니다.
- 리빙독 반영 후보는 현재 문서에 반영할 사실, 아직 반영하면 안 되는 추론, 사용자 확인 필요를 분리합니다.

## 출력 규칙

- 이해를 실질적으로 높여준다면 Mermaid 다이어그램 또는 비교 표를 최소 1개 포함합니다.
- 검증된 사실, 추론된 결론, 권장 조치를 구분해서 작성합니다.
- 트러블슈팅이나 리팩토링 보고서라면 기대 효과와 트레이드오프를 함께 설명합니다.
- 포스트모템은 timeline, impact, root cause, detection gap, action item을 포함합니다.
- ADR은 context, decision, considered options, consequences, rollback plan을 포함합니다.
- 전체 리포트는 프로젝트 전체 관점의 핵심 결론, 범위, 근거, 리스크, 후속 액션, 리빙독 반영 후보를 포함합니다.
