# 문서 인테이크 라우터
기획 목적의 "기획 문서" 요청은 바로 개발 문서로 보내지 않는다. 먼저 현재 기획 단계가 아이디어 검토, 디자인 방향 탐색, 개발 착수 중 무엇인지 분류하고, 단계에 맞는 문서 패키지를 선택한다.

문서 목적 자체가 기획인지 애매하면 먼저 `document_purpose_router.md`를 읽는다. 운영 문서, 온보딩 문서, 사용자 가이드, 데이터/보안 정책, KPI 문서처럼 기획이 아닌 상시 문서는 `living_document_package_matrix.md`로 보낸다.

## 분류 순서
1. 사용자가 만들고 싶은 것이 아직 제품/개발로 확정되지 않았으면 `아이디어 기획`이다.
2. 사용자가 경험, 감성, 화면 느낌, 레퍼런스, UX 방향을 비교하고 싶어 하면 `디자인 기획`이다.
3. 사용자가 POC, MVP, PRD, 기능, 화면, API, DB, 일정, 구현, QA를 언급하면 `개발 착수 기획`이다.
4. 하나의 요청에 여러 단계가 섞이면 앞단부터 처리한다. 아이디어가 불명확하면 디자인/개발 문서를 확정하지 않는다. 디자인 방향이 불명확하면 개발 문서를 확정하지 않는다.

## 단계별 트리거
| 단계 | 사용자 표현 | 우선 reference | 만들지 말아야 할 것 |
|---|---|---|---|
| 아이디어 기획 | 아이디어 정리, 사업 아이템, 가능성 봐줘, 어떤 방향이 좋을까 | `idea_planning_package.md` | API, DB, QA, 상세 기술 설계 |
| 디자인 기획 | 디자인 방향, 레퍼런스, UX가 맞는지, 어떤 톤이 좋을지 | `design_planning_package.md` | 확정 디자인 시스템, 상세 API, 개발 일정 |
| 개발 착수 기획 | 앱 만들자, POC 만들자, MVP 만들자, PRD 만들자, 개발 문서, 요구사항, 화면/API/일정/QA | `planning_document_package.md` | 근거 없는 아이디어 검증 문서 반복 |

## 자동 판별이 애매한 경우
- 질문은 1-3개만 한다.
- 추천 판별을 함께 제시한다.
- 사용자가 "알아서 초안"을 원하면 가장 앞단인 아이디어 기획으로 시작하고, 개발 의도가 강하게 드러난 항목만 `가정`으로 표시한다.

## 판별 질문 예시
```markdown
이 기획은 세 방향으로 갈 수 있습니다.

- 아이디어 검토: 이 아이템이 해볼 만한지 검증하는 문서
- 디자인 기획: 어떤 경험/인상/화면 방향이 맞는지 비교하는 문서
- 개발 착수: 요구사항, 화면, 기술, 일정, QA까지 만드는 문서

현재 표현만 보면 디자인 기획이 먼저 맞아 보입니다. 이 방향으로 초안을 만들까요?
```

## 단계 전환 규칙
- 아이디어 기획에서 핵심 사용자, 문제, 가치, 검증 기준이 정해지면 디자인 기획 또는 개발 착수로 전환할 수 있다.
- 디자인 기획에서 추천 방향과 버릴 방향이 정해지면 개발 착수 문서의 `design-brief.md`로 승격할 수 있다.
- 개발 착수로 전환할 때는 이전 단계 문서를 삭제하지 않고 근거 문서로 연결한다.
